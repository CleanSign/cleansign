# 정답 라벨 데이터셋 (Step 1) — 스펙 & 소싱 계획

목적: `Risk = L_max × P_realize` 정량화 모델을 검증할 수 있게 만드는 것.
지금까지는 이 모델에 "정답"이 없었다 — Jaccard 유사도를 OLS로 변환한다고 했지만
어떤 데이터로 그 회귀를 적합했는지, P_realize의 실제 관측값이 무엇인지 정의된 적이 없다.
이 문서는 그 정답을 어떻게 모으고 라벨링할지 정의한다.

## 0. 반드시 먼저 읽을 것 — P_realize의 의미론

분쟁조정/판결 기록에서 얻는 비율은 **P(손실 | 조항 ∧ 분쟁이 실제로 발생함)** 이지,
**P(손실 | 조항)** 이 아니다. 같은 독소조항이 들어간 계약인데 아무 문제 없이 만기까지 간
사례는 애초에 분쟁 기록에 나타나지 않는다 (생존자 편향).

- 이 데이터셋이 만드는 것: 조건부 현실화 비율 (`realized_ratio_conditional`).
- 이 데이터셋이 만들지 않는 것: "이 조항이 있으면 몇 %의 확률로 분쟁이 발생하는가" (기저율).
  기저율은 국토부/소비자원 집계 통계에서 별도로 추정해야 하는 문제이며, **Step 4에서 결합**한다.
  이 둘을 지금 섞으면 안 된다.
- 제품 UI에 "예상 손실액"을 무조건부 확률처럼 보여주고 싶다면, 나중에
  `P(loss) = P(dispute | clause) × P(realize | clause, dispute)` 로 명시적으로 분리해서 계산해야 한다.

## 1.1 실제로 34건을 확보하고 나서 발견한 것 (중요 — 방향 전환)

한국부동산원·LH 조정사례 게시판(`adrhome.reb.or.kr`, boardNo=11)에서 주택 태그가 붙은
34건을 전수 다운로드하고 전부 읽었다. 결과:

- **34건 중 "특약" 언급이 있는 건은 3건, 그중 조항 원문을 그대로 인용한 건은 1건뿐**
  (REB-ADR-34, "수도세는 매달 10,000원으로 한다").
- 나머지 대부분은 **성문화된 독소조항이 아니라 법정 권리(계약갱신요구권, 차임연체 해지,
  수선의무 분담, 보증금 동시이행 등)를 둘러싼 사실관계·법리 다툼**이다. 즉 "이 조항 문구
  때문에 손해를 봤다"가 아니라 "이 상황에서 법이 뭐라고 하는지"가 쟁점인 사건들이다.
- 손해액도 조항에서 기계적으로 산출되는 게 아니라 **조정위원회가 양측을 설득해 협상한
  금액**(예: 잔존가치×과실비율, 청구액의 일부만 인정 등)인 경우가 대부분이다.

**결론: 이 소스는 `clause_text_verbatim` + `realized_ratio_conditional` 쌍을 만드는
원래 목적(스키마 2번)에는 맞지 않는다.** 억지로 끼워맞추지 않고 다른 용도로 쓴다:

- **용도 전환**: 34건을 `severity_dataset_adrhome.csv`로 별도 저장했다. 여기엔
  `E[손해액 | 분쟁유형 T]` — 즉 각 분쟁 유형이 실제로 발생했을 때 얼마가 오가는지의
  분포가 담겨 있다. 이건 Risk 공식의 "심각도(severity)" 절반을 실제 숫자로 뒷받침하는
  독립적인 자료다.
- **L_max 공식의 실제 근거**: 이 중 세 건은 L_max 산정 규칙에 직접 쓸 수 있는 법적
  공식/판례를 준다.
  - REB-ADR-30: 서울중앙지법 2005가합100279 — 원상복구 관련, "통상손모"는 계약서에
    구체적으로 명시된 특약이 없는 한 임차인이 아니라 임대인이 부담한다는 법리. 즉
    "원상복구 조항이 독소조항인지"를 가르는 실제 법적 기준이 여기 있다 (조항이 통상손모
    범위까지 임차인에게 떠넘기면 그게 독소조항).
  - REB-ADR-50: 주임법 제6조의3⑥ 법정 손해배상 산식(환산월차임 3개월분 / 2년 차액 /
    실손해 중 최댓값)이 실제 적용된 사례. `묵시적갱신배제`형 L_max 공식의 근거로 그대로
    쓸 수 있다.
  - REB-ADR-56: 원상복구 청구액(3,500,000원) 대비 최종 인정액(1,000,000원, 28.6%) —
    "임대인이 부르는 금액"과 "실제 인정되는 금액" 사이의 괴리 크기를 보여주는 실측치.

**던져진 질문 (Step 4로 넘기되 지금 기록해둠)**: 이 발견은 논문의 분해식
(자카드 유사도 → OLS → P_realize, "조항 텍스트가 손실 확률을 예측한다")이 실제 데이터와
안 맞을 수 있다는 뜻이다. 주임법 제10조상 임차인에게 불리한 특약은 원래 무효라서, 손실은
"조항이 집행돼서"가 아니라 "조항과 무관하게 분쟁 자체가 발생해서" 생기는 경우가 많다.
데이터가 실제로 뒷받침하는 분해는 오히려:

```
Risk = P(이 조항이 T유형 익스포저를 만든다) × E[손해액 | T유형 분쟁 발생]
```

에 가깝다. 두 번째 항은 이번에 확보한 severity 데이터가 준다. 첫 번째 항("이 조항이
있으면 T유형 분쟁으로 이어질 확률")은 RAG가 이미 하고 있는 일(유사 사례 검색)과 겹친다 —
즉 클로즈 텍스트의 역할이 "손실 확률 예측"이 아니라 "익스포저 유형 분류"로 바뀔 수 있다는
뜻이다.

**결정(확정): 이 분해식을 채택한다.**

```
Risk = P(dispute_type = T | clause) × E[손해액 | T유형 분쟁 발생]
```

- `E[손해액 | T]` — **Step 1 산출물**. `severity_dataset_adrhome.csv`에서 clause_type별로
  집계한다 (아래 1.3절 표 참고).
- `P(dispute_type = T | clause)` — **RAG의 검색·분류 결과를 그대로 쓴다.** 새 회귀 모델을
  따로 만들지 않는다. RAG가 top-k 유사 판례를 반환할 때 "이 조항이 어떤 유형(T)의 분쟁을
  일으킬 소지가 있는지"를 이미 판단하고 있으므로, Jaccard-OLS를 이 확률의 근사치로 쓰던
  방식을 버리고 RAG의 분류 신뢰도를 직접 쓴다.
- **버려지는 것**: 자카드 유사도 → OLS 선형변환 → [0,1] 클리핑 체인 전체. 이 체인이 예측하려던
  대상(조항과 과거 조항의 표면적 유사도가 손실 확률과 비례한다는 가정)이 데이터로 뒷받침되지
  않기 때문이다.
- **알려진 약점(오버셀 방지용으로 명시)**: `P(dispute_type = T | clause)`를 정밀한 확률값으로
  추정하는 것 자체는 여전히 어렵다 — "이 조항이 있는 계약 중 몇 %가 실제 분쟁으로 번지는가"의
  분모(분쟁화되지 않은 계약 전체)를 아는 공개 데이터가 없기 때문이다. Step 4에서는 이걸 정밀한
  확률이 아니라 **심각도 등급(예: 상/중/하)** 정도의 근사치로 다루는 게 현실적이다. "우리
  모델이 분쟁 확률을 몇 %로 예측한다"는 식의 과장된 정밀도 주장은 하지 않는다.
- **또 다른 약점 — "침묵 순응(silent compliance)" 편향**: 국토교통부·법무부 해설집(2020.8)에서
  확인했듯, 임차인에게 불리한 특약은 법 제10조상 항상 무효다. 그런데 우리가 모으는 조정·판결
  데이터는 전부 **누군가 이의를 제기해서 다툰 사건**이다. 정보가 부족해서 조항이 무효인 줄
  모르고 그냥 돈을 내거나 짐을 싸서 나간 임차인은 애초에 이 데이터에 잡히지 않는다. 즉 우리가
  구할 수 있는 `realized_ratio_conditional`은 "다퉜을 때 손해"의 하한선이지, Clean Sign이
  실제로 막으려는 "몰라서 그냥 당하는" 손실의 크기가 아니다. 후자가 오히려 이 제품의 핵심
  가치(정보 비대칭 해소)에 더 가깝지만, 정의상 관측이 안 된다 — 이건 데이터로 못 채우는
  구조적 한계이니 제품 설명에서 "실측 기반"이라고 과장하지 않는다.

| 표본 수 | 17 (대부분 `원상복구과도부담`, 12건) |

즉 **분쟁이 조정까지 간 사건에서 청구인(주로 임대인)의 최초 청구액은 평균적으로 최종
인정액의 약 3배**다. 이건 L_max/P_realize 모델 설계에 두 가지로 쓸 수 있다:
1. 제품 UI에서 "예상 손실액"을 임대인의 (가상)청구액 그대로 보여주면 실제보다 약 3배
   과대추정하게 된다 — 표시할 때 이 경험적 할인율(중앙값 33%)을 곱해서 보여주는 게
   더 현실적인 기대값에 가깝다.
2. 표본이 아직 17건뿐이고 `원상복구과도부담`에 쏠려 있어(`묵시적갱신배제`는 1건뿐),
   지금 이 숫자를 곧바로 전체 clause_type에 일반화하면 안 된다 — Step 2(평가 하네스)
   에서 유형별로 따로 봐야 한다.

**읽는 법과 주의점**:
- 표본이 2~3건 수준이라 평균/중앙값은 "이 정도 규모"라는 감 정도로만 쓴다 — 통계적으로
  유의미한 추정치가 아니다. Step 1.4(향후 확장)에서 표본을 늘리기 전까지 이 숫자를 제품에
  그대로 노출하면 안 된다.
- **`선순위근저당` / `보증금반환제한` / `기타불이익` 세 유형은 이 소스에서 0건이다.** adrhome
  조정위원회는 개별 세대 단위 민사 분쟁을 다루는 곳이라, 애초에 선순위근저당(전세사기성)이나
  "조건부 반환 거절" 같은 구조적 유형은 여기로 오지 않고 형사고소·판결로 간다. 이 세 유형의
  severity 데이터는 **law.go.kr 판례 검색으로 별도 확보해야 한다** (1.3절 진행 결과 참고).
- `(통계적 분쟁, clause 무관)` 행은 `N/A_statutory` 태그가 붙은 14건이다 — 애초에 조항과
  무관한 법정 권리 다툼이라 Risk 모델의 입력으로 쓰지 않는다. 참고용으로만 남겨둔다.

이 adrhome 게시판에는 없다는 게 확인됐으니, 다른 소스가 필요하다. 후보와 각각의 한계:

`data/labeling/clause_text_leads.md` 참고.

## 2. 스키마

한 행 = 한 사건(case) 안의 한 조항(clause). 한 사건에 조항이 여러 개면 여러 행으로 쪼갠다.

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `case_id` | string | 출처+사건번호, 예: `REB-2025-032` |
| `clause_id` | string | `case_id` + 조항 순번, 예: `REB-2025-032-C1` |
| `source_type` | enum | `조정성립` / `조정불성립` / `판결` / `표준계약서` / `공식해설`(정부 발간 해설서·FAQ — 구체적 사건이 아니라 일반 법리 진술인 행에 사용, `dispute_occurred=false`로 표시) |
| `source_citation` | string | 원문 추적 가능한 출처(문서명, 페이지, 사건번호) |
| `clause_type` | enum | `선순위근저당` / `보증금반환제한` / `원상복구과도부담` / `묵시적갱신배제` / `기타불이익` / `정상` |
| `clause_text_verbatim` | string | 조항 원문 그대로 (가공 전) |
| `clause_text_normalized` | string | 전처리 후 텍스트 (파이프라인 입력용) |
| `deposit_amount` | int(원) | 계약 보증금 총액 — L_max 산정의 기준값 |
| `attribution` | enum | `single`(손해를 이 조항 하나로 귀속 가능) / `mixed`(여러 쟁점 혼재) / `none`(조항은 있으나 분쟁 미발생) |
| `mechanism` | enum | `clause_driven` / `counterparty_insolvency` / `other` — 아래 3번 참고 |
| `L_max_formula_type` | enum | 아래 4번 표의 유형 코드 |
| `L_max_value` | int(원) | 산정된 최대 잠재 손실액 |
| `dispute_occurred` | bool | 이 조항이 실제 분쟁으로 이어졌는지 |
| `actual_loss_amount` | int(원), nullable | 조정/판결로 확정된 손해액·공제액. `attribution=mixed`면 이 조항 기여분만 분리 가능할 때만 채우고, 안 되면 비워둔다 |
| `realized_ratio_conditional` | float[0,1], nullable | `actual_loss_amount / L_max_value`. **오직 `dispute_occurred=true` & `attribution≠mixed`인 행에서만 회귀 학습에 사용** |
| `outcome` | enum | `임차인전부승` / `임차인일부승` / `임차인패소` / `조정불성립` |
| `annotator_id` | string | 라벨링한 사람 (일치도 측정용) |
| `annotation_date` | date | |
| `notes` | string | 애매한 판단에 대한 자유 서술 |

## 3. 라벨링 규칙 (반드시 지킬 것 — 안 지키면 라벨러 간 데이터가 서로 호환 안 됨)

**규칙 1 — 귀속(Attribution).**
한 사건에 조항이 여러 개 걸려 있고 손해액이 하나로 뭉쳐 나오면, 조정문/판결문이 어느 조항
때문에 얼마가 나왔는지 분리해서 설명하는 경우에만 `single`로 표시하고 각 조항에 해당 금액을
배분한다. 분리가 안 되면 `mixed`로 표시하고 `actual_loss_amount`는 비워둔다 — 이 행은 회귀
학습에서 제외하되, 데이터셋에는 남겨둔다(나중에 다른 분석에 쓸 수 있음).

**규칙 2 — 손실 메커니즘(Mechanism) 태깅.**
전세사기 사건처럼 손해액이 매우 크지만, 원인이 조항 문구 자체가 아니라 임대인의 도산·잠적,
근저당 설정 순위 같은 별개 요인인 경우가 있다. 이런 사건을 태그 없이 그대로 P_realize 학습에
넣으면 모델이 "조항이 있으면 보증금 전액을 잃는다"로 잘못 수렴한다.
- `clause_driven`: 손해의 원인이 조항의 법적 효과 자체 (예: 조항 때문에 원상복구비를 과다
  청구당함)
- `counterparty_insolvency`: 임대인 도산/사기/잠적이 근본 원인, 조항은 부수적
- `other`: 위 둘로 분류 안 되는 경우
`counterparty_insolvency`는 회귀 학습에서 기본적으로 제외한다.

**규칙 3 — L_max는 도출이 아니라 정책 결정이다.**
조항 유형별로 아래 공식을 쓴다. 공식이 명확하지 않은 유형은 보증금 상한(cap)으로 문서화한다 —
"어차피 다 보증금 전액"이라고 뭉개지 말고, 유형별로 다르게 정의된 규칙이라는 걸 명시한다.

| clause_type | L_max_formula_type | 공식 |
|---|---|---|
| 선순위근저당 | `SENIOR_LIEN` | `min(deposit_amount, max(0, 근저당설정액 + 선순위채권 − 예상매각가))`. 근저당액을 모르면 fallback = `deposit_amount` |
| 보증금반환제한 | `DEPOSIT_DELAY` | 지연배상 성격이면 `지연일수 × 법정이자율 × deposit_amount`, 아니면 fallback = `deposit_amount` |
| 원상복구과도부담 | `RESTORATION` | **(2026-09-28 갱신)** `임차인 부담비용 = 수선비용 × [1 − (시설물경과연수/수선주기)]` — LH 공식 기준 제11조의 실제 산식. 항목별(도배/장판/씽크대/현관문/전기설비 등 39개 표, 무려 200+ 세부 항목) 임대인·임차인 부담 구분표를 `data/labeling/official_sources/lh_원상복구기준_별표_전체.txt`에 통째로 확보함 — 이제 "이 조항이 노후·자연손모 항목까지 임차인에게 떠넘기는가"를 이 표와 대조해서 기계적으로 판별 가능. 견적액 자체가 없으면 fallback = `deposit_amount`의 정책 상한(라벨링 중 확정) |
| 묵시적갱신배제 | `RENEWAL_BLOCK` | 이사비용 + 중개수수료 + 공백기간 월세 추정치의 합 |
| 기타불이익 | `OTHER_CAP` | case-by-case, fallback = `deposit_amount` |

**규칙 4 — 표본 배분.**
기존 N=100의 유형 비율(선순위근저당 28% / 보증금반환제한 24% / 원상복구 18% / 묵시적갱신배제
16% / 기타 14%)을 유지하되, 이번 단계에서는 **`attribution=single` & `dispute_occurred=true`
행을 유형별 최소 15건씩** 확보하는 걸 우선한다 — 이게 회귀 적합에 실제로 쓸 수 있는 표본이다.
못 채우는 유형이 있으면 억지로 채우지 말고 "이 유형은 조정사례집만으로는 표본 부족"이라고
기록하고 판결문 소스로 보충 여부를 다음 단계에서 판단한다.

**규칙 5 — 이중 라벨링.**
최소 20건은 두 명이 독립적으로 라벨링하고 `attribution`/`mechanism` 일치도(Cohen's kappa)를
계산한다. 일치도가 낮으면 규칙 자체가 애매하다는 뜻이니 규칙을 다시 쓰지, 라벨을 억지로
맞추지 않는다.

## 4. 다음 단계와의 경계

이 데이터셋이 끝나면 나오는 것: 조항 유형별 `(clause_text, L_max, realized_ratio_conditional)`
표본. 이게 Step 2(평가 하네스)에서 held-out split으로 나뉘고, Step 4(모델 개선)에서
Jaccard-OLS 방식과 "유사판례 중 실제 패소 비율" 방식을 같은 표본으로 비교하는 데 쓰인다.
기저율(분쟁 발생 확률) 추정은 여기 포함하지 않는다 — 별도 작업이다.
