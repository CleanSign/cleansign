## toxic_clauses_100.csv

생성: `cd ai-service && uv run python ../scripts/data/parse_toxic100.py` (PDF → CSV, 재실행하면 덮어쓴다).

- 100행 전부 들어 있다 (보고서 번호 1~100, 유형별 20개씩).
- **12개 행(9, 26, 28, 45, 61, 66, 77, 83, 86, 89, 95, 98)은 PDF 표의 칸이 줄바꿈으로 뒤섞여 자동 분리가 안 돼 사람이 복원했다.** `parse_note` 열에 표시했고, 복원값은 스크립트의 `MANUAL_FIX`에 있다. 단어는 PDF 그대로이고 순서만 바로잡았다.
- `report_ref_no`: 근거 끝에 붙어 있던 숫자. 보고서 참고문헌 번호로 보이며, 원문 참고문헌 목록과 대조하지는 않았다.

### 쓰기 전에 알아야 할 것

1. **`legal_effect_report`와 근거 법령·판례는 보고서의 2차 정리다.** 판례 번호와 효력 판단을 원문 판결로 검증하지 않았다. 정답 라벨로 쓰기 전에 항목별 검증이 필요하다.
2. **100개가 모두 독소 조항은 아니다.** 효력이 `유효`(5), `유효 가능`(3), `기각`(1), `권고적`(1)인 행이 있어서, 이 행들은 오히려 "독소로 오인하기 쉬운" 경계 사례다. 독소 정답 세트로 쓸 때는 제외하거나 따로 다룬다.
3. **`clause_type_auto`는 규칙 기반 초안이다.** 사생활 유형(61~100번)은 일괄 `기타불이익`, 나머지는 키워드로 정했다 (`label_status=unreviewed`). 이 README의 6유형과 보고서의 5유형은 기준이 달라서 일대일로 대응되지 않는다. 예: 95번(전출 신고 후 재전입)은 사실상 선순위 근저당 문제지만 `기타불이익`으로 분류되어 있고, `선순위근저당`은 0행이다.
4. 한 행 = 조항 예시 하나이고, 실제 사건의 손해액(`actual_loss_amount` 등)은 없다. `dataset_template.csv`의 스키마와 다르며, 같은 파일에 합치지 않았다.

## normal_clauses_standard.csv (정상 조항)

표준계약서의 본문 조항과 특약 21개. 표준 서식이므로 정의상 `clause_type=정상`이다. 생성: `python3 scripts/data/build_normal_clauses.py` (조항 문장은 이 스크립트 안에 있다).

- **OCR 교정**: Vision OCR이 서식 칸 때문에 문장을 뒤섞거나 단어를 놓친 곳이 있어, 원본 스캔 이미지와 대조해 고쳤다. 교정한 행은 `ocr_fix` 열에 내용을 적고 `label_status=needs_review`로 표시했다 (10개). 이미지로 직접 확인한 것: 제4조 ①②③④, 제6조, 제7조, 제8조, 제9조, 제10조, 제12조, 제13조, 특약. **제2조는 이미지로 재확인하지 못했다.**
- **짝이 되는 독소 조항**: `paired_toxic_type`, `paired_toxic_nos`에 같은 주제의 독소 조항(`toxic_clauses_100.csv`의 번호)을 적었다. 예: 제9조(통상 손모는 원상복구 의무 아님) ↔ #21 "모든 수리는 임차인 비용". 같은 주제인데 정상인 문장이라, 분류기가 주제어만 보고 위험으로 판단하는지(오탐) 가려내는 데 쓴다. 짝 번호는 키워드로 고른 초안이다.
- **한계**
  - 21개뿐이고 표준 서식 문장이라 "교과서적인 정상"이다. 실제 계약서의 애매한 정상 특약은 없다.
  - 기입란은 `____`로 남겨 두었고, 체크박스 항목(분쟁조정 동의 여부 등)은 문장만 뽑았다.
  - 표준 서식의 별지1 안내문(차임 증액 5% 상한 등)은 조항이 아니라 해설이라 넣지 않았다.
  - 논문의 정상 조항 50개에는 못 미친다.
